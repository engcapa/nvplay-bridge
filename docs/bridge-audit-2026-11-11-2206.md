## 已复现和修复的问题

1. **错误正文读取失败会丢失已确认的 HTTP 状态。** 收到 503 响应头后，CDP 超时、
   断开或执行上下文失效会直接抛出 CDP 异常，自动重试层看不到已确认的 503。
   修复后保留状态及已收到的正文，记录 `cdp_read_error`，隔离标签页等待刷新，
   继续使用既有 HTTP 重试预算。客户端取消和请求总时限仍优先。
   本缺陷由审查时的确定性故障注入复现；当前现场没有观察到这一路径实际发生。
2. **成功响应被误记成客户端断开。** ASGI 完成最终响应体后也可能返回 `http.disconnect`。
   原实现将它算作取消；修复后仅在最终响应体完成前记录断开。
   修复前现场的 15 个成功响应全部误报；新实例的成功响应均记录为 false。
3. **重启前的孤立请求残留在在途统计中。** 现场曾有一个约 5.4 小时前的旧请求仍显示运行，
   与当前连接池状态不符。新增实例 ID、PID、启动/停止标记，监控跨重启重建在途列表，
   并忽略旧进程的迟到请求事件。应用停止时在线程中关闭浏览器池，释放其维护线程和连接。

当前日志与 `/health` 均含实例标识，便于区分本次部署及历史记录。
工具失败中观察到文件路径/扩展名选错及 shell 命令退出错误；可比对的参数与桥接记录一致，
没有把这些模型/工具执行问题归因为桥接参数损坏。
